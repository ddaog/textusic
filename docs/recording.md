# 음악 녹음

문장을 재생한 뒤 **음악 녹음 → 녹음 끝내기 → 파일 저장**을 누릅니다. 최대 3분 또는 약 20MB까지 기록하며 재생 정지·페이지가 숨겨질 때도 녹음을 끝냅니다. 파일은 브라우저 메모리에 준비되므로 페이지를 나가기 전에 저장하세요. 다음 녹음을 완료하면 이전 임시 파일을 대체합니다.

Strudel의 최종 출력 GainNode를 MediaStreamAudioDestinationNode로 분기하여 MediaRecorder에 전달합니다. 마이크 권한은 요청하지 않으며 주변 소리는 들어가지 않습니다. 음악 녹음 버튼은 오디오만 저장합니다. 패턴 재평가로 출력 노드가 바뀌면 녹음 탭도 재연결합니다. 끊을 때는 녹음 경로만 제거하여 스피커 출력을 유지합니다.

## 시각화 영상 저장

**영상 저장 → 영상 끝내기 → 미리보기 / 공유 / 영상 파일 저장**. 현재 연의 글, 연·마디 표시, 기존 시각화(점과 EQ), 직접 음악 출력을 세로 영상으로 합칩니다. 전체 웹페이지나 입력창의 연결선은 캡처하지 않습니다. 긴 연은 16px까지 축소하고 넘치는 부분은 말줄임합니다.

540×960, 15fps, 목표 비트레이트 영상 1.5Mbps + 오디오 128kbps. 최대 60초 또는 약 16MiB(청크 도착 시 검사)로 제한합니다. 인코더에 따라 실제 비트레이트·청크 크기는 달라질 수 있습니다. 기존 시각화 프레임을 복사하고 별도 신스/FFT/외부 인코더를 실행하지 않습니다. 음악 녹음과 영상 녹화는 동시에 실행하지 않습니다. 정지·화면 숨김 시 자동 종료하며, 미리보기 재생 시 라이브 음악을 멈춰 소리 중첩을 방지합니다.

브라우저 지원 검사 후 H.264/AAC MP4 → MP4 → VP8/Opus WebM 순서로 선택합니다. Canvas captureStream + Web Audio MediaStreamDestination + MediaRecorder를 사용하므로 iOS 시스템 화면 기록을 거치지 않습니다. 아이폰의 공유 메뉴가 파일 공유를 지원하면 사진 저장 메뉴를 사용할 수 있으며, 메뉴가 제공되지 않으면 파일 다운로드가 대안입니다. 자동 사진 저장은 하지 않습니다. 파일은 브라우저 메모리에만 존재하므로 페이지를 떠나기 전에 저장해야 합니다. 새 녹화 완료 시 이전 임시 URL은 해제합니다.

지원 API가 있어도 특정 iOS 버전의 인코더 오류/검은 영상/왜곡이 없다고 보장할 수 없습니다. 실기기에서 내보낸 MP4의 영상·소리·동기화 확인이 필요합니다. 서버 업로드는 없습니다.

지원 여부를 검사해 MP4 오디오(m4a)를 우선 사용하고 WebM/Opus로 대체합니다. 형식 지원과 저장 동작은 브라우저에 따라 다릅니다. 실패하면 화면에서 안내합니다.

아이폰 화면 기록에서 왜곡되는 문제의 원인은 아직 실기기에서 확인되지 않았습니다. 지원되는 환경에 재생용 `navigator.audioSession.type = 'playback'` 힌트를 설정하고, 재생 요청 시 정지된 AudioContext를 재개합니다. 이 조치가 iOS 화면 기록의 오디오 경로·인코더를 제어하거나 문제 해결을 보장하지는 않습니다. 직접 녹음은 시스템 화면 기록을 우회하는 별도 경로입니다.

참고: [WebKit MediaRecorder](https://webkit.org/blog/11353/mediarecorder-api/), [WebKit 오디오 세션 관련 이슈](https://bugs.webkit.org/show_bug.cgi?id=218012).
