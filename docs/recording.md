# 음악 녹음

**음악 녹음 → 녹음 끝내기 → 파일 저장**을 누릅니다. 재생 버튼을 먼저 누를 필요가 없습니다. 기존 연주를 정지하고 녹음기의 시작 이벤트를 확인한 뒤 곡을 첫 마디부터 시작합니다. 영상 저장도 동일합니다. 인코더 준비와 스케줄러의 짧은 시작 지연은 포함될 수 있지만 첫 음을 놓치지 않습니다. 최대 3분 또는 약 20MB까지 기록하며 재생 정지·페이지가 숨겨질 때도 녹음을 끝냅니다. 파일은 브라우저 메모리에 준비되므로 페이지를 나가기 전에 저장하세요. 다음 녹음을 완료하면 이전 임시 파일을 대체합니다.

## 타이핑 녹화

**타이핑 녹화 → 글 쓰기 → 타이핑 녹화 끝내기**로 입력 과정과 음악이 쌓이는 변화를 세로 영상에 담습니다. 빈 문장에서도 시작할 수 있으며 기존 글은 지우지 않습니다. 입력 이벤트마다 현재 연주 중인 마디의 장·단조 화음에 속한 부드러운 플럭 음를 합성해 음악과 같은 출력으로 녹음합니다. 일반 입력에도 같은 키 소리가 나며, ‘타이핑 소리’ 옵션으로 끌 수 있습니다. 설정은 이 브라우저에 저장되고 녹화에도 동일하게 적용됩니다. 입력창을 누를 때 기존 음악 엔진을 준비하며, 최초 로딩/브라우저 오디오 잠금이 끝나기 전의 입력음을 뒤늦게 몰아서 재생하지 않습니다. OS 키보드 소리를 웹사이트에서 대신 끌 수는 없습니다. 한글 조합 중 같은 값의 중복 이벤트는 무시하고 붙여넣기는 한 번만 발음합니다. 가까운 화음 음으로 작은 오르내림을 만들고, 한 박의 1/4 길이 이상 입력 간격을 두어 빠른 타이핑을 솎아냅니다(박자에 강제로 정렬하거나 입력음을 대기열에 쌓지는 않습니다). 최대 4음, 약 0.25~0.47초 길이, 음당 사인파 2개로 제한합니다. 부드러운 문장은 긴 감쇠와 약한 배음, 덜 부드러운 문장은 짧고 밝은 음색으로 반응합니다. 동시 발음 수가 늘면 음량을 낮추고, 타자기 노이즈는 제거했습니다. 별도 마이크·오디오 컨텍스트·샘플 다운로드는 없습니다. 영상은 기존과 동일한 최대 60초입니다.

Strudel의 최종 출력 GainNode를 MediaStreamAudioDestinationNode로 분기하여 MediaRecorder에 전달합니다. 마이크 권한은 요청하지 않으며 주변 소리는 들어가지 않습니다. 음악 녹음 버튼은 오디오만 저장합니다. 패턴 재평가로 출력 노드가 바뀌면 녹음 탭도 재연결합니다. 끊을 때는 녹음 경로만 제거하여 스피커 출력을 유지합니다.

## 시각화 영상 저장

**영상 저장 → 영상 끝내기 → 미리보기 / 공유 / 영상 파일 저장**. 입력한 전체 글(최대 2,000자), 기존 시각화(점과 EQ), 직접 음악 출력을 세로 영상으로 합칩니다. 연·마디 숫자 문구는 영상에서 표시하지 않습니다. 대신 실제 스케줄러의 현재 연을 선명하게, 다른 연은 38% 불투명도로 유지하며 강조를 부드럽게 전환합니다. 동작 줄이기 설정에서는 즉시 전환합니다. 입력과 재생 악보가 다르면 현재 연과 같은 텍스트를 새 글에서 찾아 강조하고, 일치하지 않으면 같은 순서의 연(삭제 시 마지막 연)을 잠정 강조합니다. 스타일 데이터 갱신을 기다리는 프레임에서도 전체 글이 갑자기 밝아지지 않습니다.

연을 가로지르는 연결선은 끝점별 강조를 그라데이션으로 반영합니다. 저장 영상의 비활성 연은 단어 원래 색과 무관하게 동일한 회색(#7b827e), 38% 불투명도로 표시하며 빛 번짐·물결·밑줄·단어 배경을 그리지 않습니다. 비활성 끝점도 회색 14%로 고정해 음악 에너지에 따라 진해지지 않습니다. 이전 연은 즉시 흐려지고 새 연만 부드럽게 나타납니다. UI와 영상 모두 연결선을 조금 더 굵고 선명하게 표시합니다. 모바일 최대 10개, 데스크톱 최대 14개, 단어별 최대 3개로 제한하며 중복 관계는 제거합니다.

입력창의 단어 색상·서체·효과 종류 및 동일한 정리된 연결 관계를 받아 영상 크기에 맞춰 Canvas로 다시 그립니다. 물결/점선/밑줄, 빛 번짐, 은은한 단어 배경과 단어 중앙 연결선·끝점이 포함됩니다. 선과 빛은 기존 실제 출력 스펙트럼에 반응합니다. DOM 스크린샷을 복제하는 방식이 아니므로 줄 배치와 효과의 픽셀 모양은 입력창과 다를 수 있습니다. 입력창에서 스크롤로 가려진 단어도 영상에서는 연결됩니다.

연이 바뀌어도 모든 연의 글이 유지되며, 녹화 중 입력 수정도 반영합니다. 줄바꿈과 빈 줄을 보존한 채 모든 글이 영역 안에 들어가도록 글자 크기를 조절하며 자르거나 말줄임하지 않습니다. 줄바꿈이 매우 많으면 글자가 작아집니다. 텍스트·스타일 배치는 변경 시에만 계산해 프레임별 DOM 측정 비용을 줄입니다.

540×960, 15fps, 목표 비트레이트 영상 1.5Mbps + 오디오 128kbps. 최대 60초 또는 약 16MiB(청크 도착 시 검사)로 제한합니다. 인코더에 따라 실제 비트레이트·청크 크기는 달라질 수 있습니다. 기존 시각화 프레임을 복사하고 별도 신스/FFT/외부 인코더를 실행하지 않습니다. 음악 녹음과 영상 녹화는 동시에 실행하지 않습니다. 정지·화면 숨김 시 자동 종료하며, 미리보기 재생 시 라이브 음악을 멈춰 소리 중첩을 방지합니다.

브라우저 지원 검사 후 H.264/AAC MP4 → MP4 → VP8/Opus WebM 순서로 선택합니다. Canvas captureStream + Web Audio MediaStreamDestination + MediaRecorder를 사용하므로 iOS 시스템 화면 기록을 거치지 않습니다. 아이폰의 공유 메뉴가 파일 공유를 지원하면 사진 저장 메뉴를 사용할 수 있으며, 메뉴가 제공되지 않으면 파일 다운로드가 대안입니다. 자동 사진 저장은 하지 않습니다. 파일은 브라우저 메모리에만 존재하므로 페이지를 떠나기 전에 저장해야 합니다. 새 녹화 완료 시 이전 임시 URL은 해제합니다.

지원 API가 있어도 특정 iOS 버전의 인코더 오류/검은 영상/왜곡이 없다고 보장할 수 없습니다. 실기기에서 내보낸 MP4의 영상·소리·동기화 확인이 필요합니다. 서버 업로드는 없습니다.

지원 여부를 검사해 MP4 오디오(m4a)를 우선 사용하고 WebM/Opus로 대체합니다. 형식 지원과 저장 동작은 브라우저에 따라 다릅니다. 실패하면 화면에서 안내합니다.

아이폰 화면 기록에서 왜곡되는 문제의 원인은 아직 실기기에서 확인되지 않았습니다. 지원되는 환경에 재생용 `navigator.audioSession.type = 'playback'` 힌트를 설정하고, 재생 요청 시 정지된 AudioContext를 재개합니다. 이 조치가 iOS 화면 기록의 오디오 경로·인코더를 제어하거나 문제 해결을 보장하지는 않습니다. 직접 녹음은 시스템 화면 기록을 우회하는 별도 경로입니다.

참고: [WebKit MediaRecorder](https://webkit.org/blog/11353/mediarecorder-api/), [WebKit 오디오 세션 관련 이슈](https://bugs.webkit.org/show_bug.cgi?id=218012).
